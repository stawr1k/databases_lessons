# Лекция 2: Основы работы с Redis и базовые команды

## 1. Введение и проверка подключения

Для работы с Redis используется интерактивный CLI-интерфейс (`redis-cli`). Перед началом выполнения операций рекомендуется убедиться в корректности подключения к серверу.

* **`PING`** — проверка доступности Redis-сервера.  
* **Ответ сервера:** `PONG` (соединение успешно установлено).

```redis
> PING
PONG
```

## 2. Простая установка и чтение данных (SET, GET)

В Redis данные хранятся в формате пары **«Ключ — Значение» (Key-Value)**.

Поскольку в Redis нет таблиц, ключ — это единственный способ найти данные. Чтобы в базе не было хаоса, разработчики используют общепринятый стандарт двоеточий `:` для имитации папок или пространств имен (*namespaces*).

**Шаблон эффективного ключа:** `сущность:идентификатор:поле`

* **Плохо:** `user`, `123`, `data` (непонятно, чьи это данные, их легко случайно перезаписать).
* **Хорошо:**
	* `user:1024:profile` — профиль пользователя с ID 1024 (внутри лежит JSON).
	* `article:45:views` — счетчик просмотров статьи №45 (внутри лежит число).
	* `session:tokens:user_99` — токен авторизации для пользователя 99.

> **💡 Совет:** Старайтесь делать ключи читаемыми, но не слишком длинными, так как они тоже занимают оперативную память. Например, вместо `user:id:1024:field:email` лучше написать `user:1024:email`.

### Базовые команды

* **`SET <ключ> <значение>`** — создает или перезаписывает ключ с указанным значением.  
* Значения с пробелами оборачиваются в кавычки (`SET info "My Data"`).  
* Одиночные слова можно передавать без кавычек (`SET username Alex`).  
* **`GET <ключ>`** — возвращает значение по указанному ключу.  
* Если ключа не существует в базе данных, Redis возвращает `nil`.

```redis
> SET username Alex
OK
> GET username
"Alex"
> GET non_existing_key
(nil)
```

**Хранение данных:** Данные в Redis хранятся в оперативной памяти (RAM) для максимальной скорости, а также автоматически синхронизируются с диском. При перезапуске сервера данные сохраняются.

## 3. Проверка существования и удаление ключей (EXISTS, DEL)

Помимо записи и чтения, важной частью работы с Key-Value хранилищем является проверка наличия данных и их своевременный сброс. В Redis за это отвечают атомарные команды `EXISTS` и `DEL`.

* **`EXISTS <ключ>`** — проверяет наличие ключа в базе данных. 
Перед выполнением тяжелых операций в коде (например, чтением большого JSON-профиля или запуском расчетов) часто нужно проверить, закэшированы ли уже эти данные.

* **Синтаксис:** `EXISTS ключ [ключ ...]`
* **Возвращаемое значение:** Целое число — количество найденных ключей.

**Примеры использования:**
```bash
# Проверяем один существующий ключ
EXISTS user:1024:profile
# Ответ сервера: (integer) 1  (Ключ найден)

# Проверяем несуществующий ключ
EXISTS user:999:profile
# Ответ сервера: (integer) 0  (Ключ не найден)
``` 

Возвращает `1`, если ключ существует, и `0`, если ключ не найден.  

> **⚡️ Примечание:** Начиная с версии Redis 3.0.3, команде `EXISTS` можно передать сразу несколько ключей через пробел. Она вернет общее количество существующих ключей из этого списка:

> ```bash
> EXISTS user:1024:profile user:999:profile
> # Ответ сервера: (integer) 1  (Так как первый существует, а второго нет)
> ```

* **`DEL <ключ>`** — удаляет указанный ключ и его значение из базы данных.

Команда используется для мгновенной очистки оперативной памяти от ставших неактуальными данных (например, при выходе пользователя из системы нужно удалить его сессию).

* **Синтаксис:** `DEL ключ [ключ ...]`
* **Возвращаемое значение:** Число успешно удаленных ключей.

**Примеры использования:**

```bash
# Удаляем профиль пользователя
DEL user:1024:profile
# Ответ сервера: (integer) 1  (Один ключ успешно удален)

# Пробуем удалить его повторно
DEL user:1024:profile
# Ответ сервера: (integer) 0  (Ничего не удалено, так как ключа уже нет)
```

**Множественное удаление:**

Вы можете очистить сразу несколько связанных ключей за одну команду, передав их списком:

```bash
DEL user:1024:profile article:45:views session:tokens:user_99
# Ответ сервера: (integer) 3  (Все три ключа стерты из памяти)
```


> **💡  Полезно знать:** Разница между DEL и UNLINK

Команда `DEL` выполняет удаление **синхронно**. Если значение ключа огромное (например, список или хэш-таблица на миллионы элементов), сервер Redis может «зависнуть» на доли секунды, пока полностью очищает память.

Если вам нужно безопасно удалить очень большой ключ в высоконагруженном проекте, используйте команду **`UNLINK`**:

```bash
UNLINK big:heavy:cache_key
```
Она мгновенно отвязывает ключ от пространства имен (для клиентов он сразу «исчезает»), а саму очистку памяти выполняет **асинхронно** в фоновом потоке, не блокируя основной сервер.

## 4. Множественные операции (MSET, MGET)

Для оптимизации работы и отправки нескольких значений за один запрос используются мульти-команды:

* **`MSET <ключ1> <знач1> <ключ2> <знач2> ...`** — атомарно устанавливает сразу несколько пар ключ-значение.  
&nbsp;&nbsp;&nbsp;&nbsp;Пример: `MSET User Alex hobby proger Age 23`  
* **`MGET <ключ1> <ключ2> ...`** — возвращает список значений для нескольких ключей.  
&nbsp;&nbsp;&nbsp;&nbsp;Если один из ключей отсутствует, на его месте выводится `nil`.

```redis
> MSET User Alex hobby proger Age 23
OK
> MGET User hobby Age status
1) "Alex"
2) "proger"
3) "23"
4) (nil)
```

## 5. Модификация и работа со строками (APPEND, GETRANGE, SETRANGE)

По умолчанию Redis воспринимает все значения как строковые данные (Strings).

* **`APPEND <ключ> <текст>`** — добавляет указанный текст в конец существующего строкового значения. Возвращает итоговую длину строки.  
* **`GETRANGE <ключ> <старт> <конец>`** — выбирает подстроку по индексам.  
* Поддерживает отрицательные индексы (например, `-1` означает последний символ).  
&nbsp;&nbsp;&nbsp;&nbsp;Пример: `GETRANGE User 0 -1` выведет всю строку, а `GETRANGE User -3 -1` выведет последние 3 символа.  
* **`SETRANGE <ключ> <смещение> <текст>`** — перезаписывает часть строки новым текстом, начиная с указанного индекса.

```redis
> SET greeting "Hello"
OK
> APPEND greeting " World"
(integer) 11
> GETRANGE greeting 0 4
"Hello"
> SETRANGE greeting 6 "Redis"
(integer) 11
> GET greeting
"Hello Redis"
```

## 6. Числовые операции (INCR, DECR, INCRBY, DECRBY)

Если сохраненная строка состоит строго из цифр, Redis умеет обрабатывать ее как число.

| Команда | Описание | Пример |
| :--- | :--- | :--- |
| `INCR <ключ>` | Увеличивает числовое значение ключа на 1 | `INCR page_views` |
| `DECR <ключ>` | Уменьшает числовое значение ключа на 1 | `DECR stock_count` |
| `INCRBY <ключ> <число>` | Увеличивает значение на заданный шаг | `INCRBY score 15` |
| `DECRBY <ключ> <число>` | Уменьшает значение на заданный шаг | `DECRBY balance 50` |

```redis
> SET visits 100
OK
> INCR visits
(integer) 101
> INCRBY visits 50
(integer) 151
> DECRBY visits 10
(integer) 141
```

## 7. Пространства имен и структура ключей

В Redis нет таблиц, поэтому иерархия создается за счет логического именования ключей через двоеточие `:` или точку `.`.

### Примеры именования:

* `User:1001:name` → Alice  
* `User:1001:email` → alice@example.com  
* `User:1002:name` → Bob

Это позволяет структурировать данные и визуально разделять сущности в плоском пространстве ключей.

## 8. Управление ключами и очистка базы

* **`KEYS *`** — выводит список всех существующих ключей в текущей базе данных.  
* **`RENAME <старый_ключ> <новый_ключ>`** — переименовывает ключ.  
* **Установка времени жизни (TTL / EX):**  
&nbsp;&nbsp;&nbsp;&nbsp;`SET <ключ> <значение> EX <секунды>` — задает время жизни ключа в секундах, после чего он автоматически удаляется.  
* **Условное сохранение (NX):**  
&nbsp;&nbsp;&nbsp;&nbsp;`SET <ключ> <значение> NX` — устанавливает ключ только в том случае, если он еще не существует.  
* **`FLUSHDB`** — полностью очищает текущую базу данных от всех ключей.

```redis
> SET session:tok123 "active" EX 60
OK
> SET lock:resource "busy" NX
OK
> RENAME User:1001:name User:1001:fullname
OK
> FLUSHDB
OK
```
