# Лекция 2: Основы SQL: Создание баз данных, таблиц, типы данных и CRUD-операции

## 1. Введение и управление базами данных

В MySQL все данные группируются по **базам данных** (в терминологии MySQL термины *Database* и *Schema* являются полными синонимами). Перед тем как создавать таблицы и сохранять строки, необходимо создать базу данных и переключить активный контекст.

### Команды управления базами данных

* **`CREATE DATABASE`** — создает новую базу данных.
* **`SHOW DATABASES;`** — выводит список всех баз на текущем сервере.
* **`USE <имя_базы>;`** — делает базу активной для всех последующих SQL-запросов текущей сессии.
* **`SELECT DATABASE();`** — возвращает имя текущей выбранной базы.
* **`DROP DATABASE`** — безвозвратно удаляет базу данных со всеми её таблицами.

```sql
-- Создание базы данных с явным указанием кодировки utf8mb4 (полная поддержка любых языков и эмодзи)
CREATE DATABASE IF NOT EXISTS shop_db 
CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

-- Переключение на созданную базу
USE shop_db;

-- Проверка активной базы
SELECT DATABASE();
```

> **💡 Совет по кодировкам:** Всегда используйте кодировку **`utf8mb4`** вместо устаревшей `utf8`. Исторический `utf8` в MySQL резервировал максимум 3 байта на символ и не поддерживает современные эмодзи (например, 🚀, 📦) и некоторые редкие символы, что приводило к ошибке `Incorrect string value`. Стандарт `utf8mb4` использует честные 4 байта и является отраслевым стандартом.

## 2. Типы данных в MySQL

Правильный выбор типов данных определяет производительность, размер занимаемой памяти на диске и целостность информации.

| Категория | Тип данных | Размер | Назначение и примеры |
| :--- | :--- | :--- | :--- |
| **Целые числа** | `TINYINT` | 1 байт | Диапазон -128..127. Часто используется как логический флаг (`BOOLEAN`). |
| | `INT` (INTEGER) | 4 байта | До ~2.1 млрд. Стандарт для большинства идентификаторов и счетчиков. |
| | `BIGINT` | 8 байтов | Огромные числа (до $9 \times 10^{18}$). Для крупных сервисов с миллионами записей. |
| **Дробные числа** | `DECIMAL(M, D)` | Переменный | **Точные фиксированные числа**. Незаменим для цен и денег: `DECIMAL(10, 2)` (до 10 цифр, 2 знака после запятой). |
| | `FLOAT / DOUBLE` | 4 / 8 байт | Числа с плавающей точкой. Подвержены погрешностям округления. Нельзя использовать для финансов! |
| **Строки** | `VARCHAR(N)` | До $N$ символов | Строка переменной длины (до 65 535 байт). Например: `VARCHAR(255)` для email. |
| | `CHAR(N)` | Фиксированный $N$ | Строка строго фиксированной длины. Удобно для хешей, кодов стран (`CHAR(2)`: 'RU', 'KZ'). |
| | `TEXT` | До 64 КБ | Длинные статьи, комментарии, описания. Хранится вне основной строки таблицы. |
| **Дата и время** | `DATE` | 3 байта | Только дата в формате `'YYYY-MM-DD'` (например, `'2026-10-18'`). |
| | `DATETIME` | 5 байт | Дата и время без привязки к таймзоне: `'2026-10-18 21:00:00'`. |
| | `TIMESTAMP` | 4 байта | Дата и время в формате эпохи Unix (хранится в UTC). Идеально для `created_at`. |
| **Логический** | `BOOLEAN` | 1 байт | Синоним `TINYINT(1)`. Принимает значения `TRUE` (1) или `FALSE` (0). |
| **JSON** | `JSON` | Переменный | Нативное хранение структурированных документов с валидацией синтаксиса. |

## 3. Ограничения целостности (Constraints)

Ограничения предотвращают попадание некорректных данных в таблицу на уровне ядра СУБД:

* **`PRIMARY KEY` (Первичный ключ):** Уникальный маркер записи. Не может содержать `NULL`. Каждая таблица обязана иметь первичный ключ.
* **`AUTO_INCREMENT`:** Автоматическая генерация следующего целочисленного ID при вставке строки (1, 2, 3...).
* **`NOT NULL`:** Запрещает сохранять пустое значение (`NULL`). Поле становится обязательным.
* **`UNIQUE`:** Гарантирует уникальность значений во всей колонке (например, запрещает регистрацию пользователей с одинаковым email).
* **`DEFAULT <значение>`:** Подставляет значение по умолчанию, если оно не было передано при вставке (например, `DEFAULT CURRENT_TIMESTAMP` или `DEFAULT 0`).
* **`CHECK (условие)`:** Проверяет логическое условие на валидность значений (например, `CHECK (price >= 0)`).

## 4. Создание и изменение структуры таблиц (DDL)

### Создание таблицы (CREATE TABLE)

Создадим таблицу пользователей `users` и таблицу товаров `products`:

```sql
CREATE TABLE IF NOT EXISTS users (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    age TINYINT UNSIGNED CHECK (age >= 14 AND age <= 120),
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE IF NOT EXISTS products (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    title VARCHAR(150) NOT NULL,
    description TEXT,
    price DECIMAL(10, 2) NOT NULL CHECK (price >= 0.00),
    stock_quantity INT NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
```

### Просмотр структуры таблицы

```sql
-- Показать список таблиц текущей базы
SHOW TABLES;

-- Просмотреть описание колонок, типов и ключей таблицы
DESCRIBE users;

-- Получить точный SQL-код, которым была создана таблица
SHOW CREATE TABLE users;
```

### Изменение структуры таблицы (ALTER TABLE)

В процессе эволюции приложения структуру базы данных регулярно приходится дорабатывать:

```sql
-- Добавление новой колонки
ALTER TABLE users ADD COLUMN phone VARCHAR(20) NULL AFTER email;

-- Изменение типа или параметров существующей колонки
ALTER TABLE users MODIFY COLUMN username VARCHAR(80) NOT NULL;

-- Переименование колонки
ALTER TABLE users RENAME COLUMN phone TO mobile_phone;

-- Удаление колонки
ALTER TABLE users DROP COLUMN mobile_phone;
```

### Очистка и удаление таблиц

* **`DROP TABLE <имя>;`** — полностью стирает таблицу и её схему из базы данных.
* **`TRUNCATE TABLE <имя>;`** — мгновенно удаляет все строки из таблицы и сбрасывает счетчик `AUTO_INCREMENT` в 1 (работает намного быстрее, чем `DELETE FROM table`).

```sql
-- Полное удаление таблицы
DROP TABLE IF EXISTS old_table;

-- Очистка всех записей с сохранением структуры
TRUNCATE TABLE products;
```

## 5. Манипуляция данными: Базовые CRUD-операции (DML)

Аббревиатура **CRUD** обозначает четыре базовые операции работы с данными: **C**reate (Создание), **R**ead (Чтение), **U**pdate (Обновление) и **D**elete (Удаление).

### 1. Create: Вставка записей (INSERT INTO)

#### Одиночная вставка:

```sql
INSERT INTO users (username, email, age) 
VALUES ('alex_dev', 'alex@example.com', 24);
```

#### Множественная пакетная вставка (Batch Insert):
Пакетная вставка одной командой выполняется в десятки раз быстрее, чем отправка десятков отдельных `INSERT`:

```sql
INSERT INTO users (username, email, age) VALUES 
('olga_k', 'olga@example.com', 28),
('ivan_petrov', 'ivan@example.com', 35),
('elena_m', 'elena@example.com', 19);
```

#### Обработка конфликтов уникальности (UPSERT):

```sql
-- Если запись с таким email уже есть, не падать с ошибкой, а обновить возраст
INSERT INTO users (username, email, age) 
VALUES ('alex_dev', 'alex@example.com', 25)
ON DUPLICATE KEY UPDATE age = VALUES(age);
```

---

### 2. Read: Чтение данных (SELECT)

* Выборка всех полей и всех строк:
  ```sql
  SELECT * FROM users;
  ```
  *(> **Совет:** В реальном продакшен-коде избегайте `SELECT *`. Всегда перечисляйте только нужные поля — это экономит оперативную память и пропускную способность сети).*

* Выборка конкретных колонок:
  ```sql
  SELECT id, username, email FROM users;
  ```

* Вычисляемые колонки и псевдонимы (`AS`):
  ```sql
  SELECT 
      username, 
      age, 
      age + 5 AS age_in_five_years 
  FROM users;
  ```

---

### 3. Update: Изменение данных (UPDATE)

Команда `UPDATE` изменяет существующие записи в таблице.

```sql
-- Обновляем возраст конкретного пользователя по его первичному ключу
UPDATE users 
SET age = 26 
WHERE id = 1;

-- Обновление нескольких колонок одновременно
UPDATE users 
SET is_active = FALSE, age = 30 
WHERE username = 'olga_k';
```

> **⚠️ КРИТИЧЕСКИ ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ:**  
> Всегда проверяйте условие `WHERE` перед запуском `UPDATE`! Если вы случайно выполните `UPDATE users SET is_active = FALSE;` без условия `WHERE`, СУБД обновит **абсолютно все строки в таблице**!

---

### 4. Delete: Удаление данных (DELETE)

Команда `DELETE` удаляет одну или несколько строк, подходящих под условие:

```sql
-- Удаление конкретной записи
DELETE FROM users 
WHERE id = 4;

-- Удаление с составным условием
DELETE FROM users 
WHERE is_active = FALSE AND age > 50;
```

> **⚠️ ПРЕДУПРЕЖДЕНИЕ:**  
> Команда `DELETE FROM users;` без блока `WHERE` сотрет все записи из таблицы! В MySQL существует защитный режим `SQL_SAFE_UPDATES = 1`, который блокирует случайные `UPDATE` и `DELETE` без указания первичного ключа в `WHERE`.

## 6. Частые ошибки начинающих разработчиков

1. **Забытый WHERE в UPDATE / DELETE:** Приводит к порче или потере всех данных в таблице. Всегда пишите `WHERE` перед выполнением модифицирующих запросов.
2. **Использование типов FLOAT / DOUBLE для финансовых данных:** Дробные типы с плавающей точкой накапливают погрешность двоичного представления ($0.1 + 0.2 = 0.30000000000000004$). Для денег используйте только **`DECIMAL(12, 2)`**.
3. **Отсутствие кодировки `utf8mb4`:** Создание таблиц в дефолтной кодировке `latin1` или старой `utf8` приводит к невозможности сохранить смайлы или национальные алфавиты.
4. **Хранение паролей в открытом виде:** Пароли пользователей никогда не сохраняются открытым текстом в `VARCHAR`. В базе сохраняется только криптографический хэш (например, bcrypt / argon2 длиной от 60 символов).
