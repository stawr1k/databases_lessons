# Лекция 1: Введение в реляционные СУБД, архитектура MySQL и развертывание

## 1. Что такое MySQL и реляционная модель данных?

**MySQL** — это одна из самых популярных, надежных и производительных реляционных систем управления базами данных (РСУБД) с открытым исходным кодом в мире.

В отличие от NoSQL-систем (таких как Redis или MongoDB), где данные часто хранятся в виде свободных пар «ключ — значение» или неструктурированных документов, MySQL базируется на классической **реляционной модели** (от англ. *relation* — отношение / таблица):

* **Строгая схема (Schema):** Данные организуются в виде двумерных таблиц с фиксированным набором колонок (полей) и их строгой типизацией.
* **Строки (Записи / Кортежи):** Каждая запись в таблице представляет собой отдельный информационный объект (например, конкретного пользователя или заказ).
* **Столбцы (Поля / Атрибуты):** Задают свойства объекта с конкретным типом данных (например, `id`, `email`, `created_at`).
* **Первичный ключ (Primary Key):** Уникальный идентификатор строки, гарантирующий, что ни одна запись не будет перепутана с другой.
* **Связи (Relations / Foreign Keys):** Таблицы связываются между собой с помощью внешних ключей, что позволяет моделировать отношения любой сложности: «один-к-одному», «один-ко-многим» и «многие-ко-многим».

Взаимодействие с базой данных происходит с помощью международного декларативного языка **SQL** (*Structured Query Language* — язык структурированных запросов). Он подразделяется на логические подмножества:

* **DDL (Data Definition Language):** Команды определения структуры базы (`CREATE`, `ALTER`, `DROP`).
* **DML (Data Manipulation Language):** Команды манипуляции данными (`INSERT`, `UPDATE`, `DELETE`).
* **DQL (Data Query Language):** Команды выборки и чтения данных (`SELECT`).
* **TCL (Transaction Control Language):** Команды управления транзакциями (`COMMIT`, `ROLLBACK`, `SAVEPOINT`).

## 2. Ключевые преимущества и причины популярности

* **Мировой промышленный стандарт:**  
&nbsp;&nbsp;&nbsp;&nbsp;MySQL используется в тысячах крупнейших IT-проектов мира (Meta, YouTube, Uber, GitHub, Booking) и лежит в основе классических веб-стеков (LAMP, LEMP, Django, Spring, FastAPI, Node.js, Laravel).
* **Надежность и поддержка стандарта ACID:**  
&nbsp;&nbsp;&nbsp;&nbsp;Благодаря современному движку **InnoDB**, MySQL гарантирует полную сохранность финансовой и корпоративной информации даже в случае внезапных сбоев электропитания или падения серверов.
* **Подключаемые движки хранения (Pluggable Storage Engines):**  
&nbsp;&nbsp;&nbsp;&nbsp;Уникальная особенность MySQL — возможность выбирать механизм хранения данных на уровне каждой отдельной таблицы (`InnoDB` для транзакций, `MEMORY` для ультрабыстрых временных таблиц в RAM, `CSV` для импорта/экспорта).
* **Высокая масштабируемость и репликация:**  
&nbsp;&nbsp;&nbsp;&nbsp;Поддерживает асинхронную и полусинхронную репликацию (Master-Replica), кластеризацию (MySQL InnoDB Cluster), шардинг и горизонтальное масштабирование.
* **Богатая экосистема и кроссплатформенность:**  
&nbsp;&nbsp;&nbsp;&nbsp;Драйверы и коннекторы доступны для любого современного языка (Python, Go, C#, Java, JavaScript/TypeScript, PHP, Rust), а также существует огромное число GUI-клиентов и инструментов администрирования.

### Сравнение: MySQL vs Redis (Когда что выбирать?)

| Критерий | MySQL | Redis |
| :--- | :--- | :--- |
| **Тип СУБД** | Реляционная (RDBMS) | In-Memory Key-Value хранилище |
| **Место хранения** | Постоянный накопитель (SSD/NVMe) + RAM-буфер | Оперативная память (RAM) |
| **Сложность структуры** | Сложные таблицы, схемы, внешние ключи, JOIN | Ключи со структурами (строки, хэши, списки, сеты) |
| **Скорость отклика** | 1–15 мс (зависит от сложности SQL и индексов) | Доли миллисекунды (< 1 мс) |
| **Объем данных** | Терабайты и петабайты информации | Ограничен объемом установленной RAM |
| **Основная роль** | **Основное постоянное хранилище** бизнес-сущностей | **Кэш, очереди задач, сессии**, брокер сообщений |

> **💡 Архитектурный совет:** В реальных проектах MySQL и Redis не конкурируют, а работают **в синергии**. MySQL берет на себя надежное хранение критически важных связанных данных (каталог, пользователи, балансы, счета), а Redis кэширует частые запросы к MySQL, снимая с него избыточную нагрузку.

## 3. Архитектура MySQL: Как сервер устроен изнутри

Архитектура MySQL построена по модульному принципу и состоит из трех основных уровней:

```
+-----------------------------------------------------------+
|          1. Уровень клиентов и соединений                 |
| (Аутентификация, авторизация, безопасность, Connection Pool)|
+-----------------------------------------------------------+
                              |
                              v
+-----------------------------------------------------------+
|          2. Уровень SQL-сервера (Ядро MySQL)               |
|  * SQL-парсер (Проверка синтаксиса и построение AST)      |
|  * Оптимизатор (Query Optimizer — выбор лучшего плана)    |
|  * Внутренние буферы, кэши метаданных и временные таблицы |
+-----------------------------------------------------------+
                              |
                              v
+-----------------------------------------------------------+
|     3. Уровень движков хранилища (Pluggable Engines)      |
|  * InnoDB (По умолчанию: транзакции, ACID, Buffer Pool)   |
|  * Memory (Хранение таблиц строго в RAM)                  |
|  * MyISAM / CSV / Archive                                 |
+-----------------------------------------------------------+
                              |
                              v
             Файловая система и физический диск
```

### Принципы ACID в InnoDB

Все современные проекты используют движок **InnoDB** (стандарт по умолчанию с MySQL 5.5+), который гарантирует выполнение свойств **ACID**:

1. **Atomicity (Атомарность):** Любая транзакция выполняется либо целиком, либо не выполняется вовсе. Если хотя бы один запрос падает — все промежуточные изменения отменяются (`ROLLBACK`).
2. **Consistency (Согласованность):** Данные до и после транзакции переходят из одного валидного состояния в другое, не нарушая внешние ключи, типы и ограничения (`CHECK`, `UNIQUE`).
3. **Isolation (Изолированность):** Параллельные транзакции не влияют друг на друга непредсказуемым образом (регулируется уровнями изоляции).
4. **Durability (Долговечность):** Если транзакция зафиксирована (`COMMIT`), изменения записаны в журнал предзаписи (*Redo Log / WAL*) и гарантированно сохранятся даже при физическом выключении питания сервера.

## 4. Основные сценарии применения MySQL в разработке

* **Учетные записи и профили:** Авторизация, роли, права доступа, персональные профили пользователей.
* **Электронная коммерция (E-Commerce):** Каталоги товаров, остатки на складах, корзины, история транзакций и заказов.
* **Финансовые и банковские сервисы:** Расчет балансов, биллинг, платежи (благодаря точным типам `DECIMAL` и транзакционности).
* **Корпоративные ERP и CRM платформы:** Сложные системы взаимосвязанных таблиц с десятками внешних ключей и ограничений.
* **Аналитические агрегации:** Подсчет метрик, отчетов за периоды времени с помощью группировок, оконных функций и обобщенных табличных выражений (CTE).

## 5. Установка и развертывание MySQL

В современной разработке актуальной версией является **MySQL 8.0+** и долгосрочная редакция **MySQL 8.4 LTS / 9.x**. Ниже приведены инструкции по установке на все популярные платформы.

### Linux (Ubuntu / Debian)

Установка через официальный пакетный менеджер `APT`:

```bash
sudo apt update
sudo apt install mysql-server -y
```

Управление системной службой:

```bash
# Проверка статуса службы
sudo systemctl status mysql

# Запуск и добавление в автозагрузку
sudo systemctl start mysql
sudo systemctl enable mysql
```

Запуск встроенного мастера безопасной настройки (установка пароля root, удаление тестовой БД и анонимных пользователей):

```bash
sudo mysql_secure_installation
```

---

### macOS

Установка через пакетный менеджер [**Homebrew**](https://brew.sh):

```bash
# Установка сервера MySQL
brew install mysql

# Запуск сервера в качестве фоновой службы
brew services start mysql

# Запуск скрипта первичной безопасности
mysql_secure_installation
```

---

### Windows и Docker (Рекомендуемый современный стандарт)

Для Windows можно использовать классический графический установщик [**MySQL Community Installer**](https://dev.mysql.com/downloads/installer/). Однако золотым стандартом для разработчиков сегодня является запуск через **Docker Desktop**. Это изолирует систему, позволяет поднимать СУБД за считанные секунды и не засоряет реестр Windows.

#### Вариант 1: Запуск одной командой через Docker CLI

```bash
docker run --name mysql-server -p 3306:3306 -e MYSQL_ROOT_PASSWORD=secret -d mysql:8.4
```

| Параметр | Описание |
| :--- | :--- |
| `--name mysql-server` | Задает человекочитаемое имя контейнера |
| `-p 3306:3306` | Пробрасывает стандартный порт MySQL с хоста в контейнер |
| `-e MYSQL_ROOT_PASSWORD=secret` | Передает пароль суперпользователя `root` |
| `-d` | Запускает контейнер в фоновом режиме (*detached*) |
| `mysql:8.4` | Официальный образ MySQL версии 8.4 LTS из Docker Hub |

#### Вариант 2: Запуск через Docker Compose (Идеально для командных проектов)

Создайте файл `docker-compose.yml` в корне вашего проекта:

```yaml
services:
  mysql:
    image: mysql:8.4
    container_name: mysql_dev
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: my_database
      MYSQL_USER: dev_user
      MYSQL_PASSWORD: devpassword
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:
```

Запуск окружения одной командой:

```bash
docker compose up -d
```

### Подключение к MySQL через консольный клиент (CLI)

После запуска сервера подключитесь к интерактивной консоли MySQL:

```bash
# Если сервер установлен локально:
mysql -u root -p

# Если сервер запущен в Docker:
docker exec -it mysql-server mysql -u root -p
```

После ввода пароля откроется консоль MySQL (`mysql>`). Выполните тестовые команды для проверки статуса:

```sql
-- Проверка текущей версии сервера
SELECT VERSION();

-- Проверка статуса соединения и настроек кодировки
STATUS;

-- Просмотр списка доступных баз данных
SHOW DATABASES;

-- Выход из интерактивной консоли
EXIT;
```

## 6. Графические клиенты (GUI) для продуктивной работы

Хотя консоль необходима для понимания основ и автоматизации скриптов, визуализировать схемы и выполнять запросы удобнее в специализированных программах:

* **[DBeaver Community](https://dbeaver.io/):** Лучший бесплатный кроссплатформенный инструмент с поддержкой автодополнения кода, построения ER-диаграмм и редактирования таблиц на лету.
* **[MySQL Workbench](https://www.mysql.com/products/workbench/):** Официальный инструмент от Oracle для администрирования, визуального проектирования схем и мониторинга сервера.
* **Расширения VS Code:** Плагин *Database Client* или *SQLTools* позволяет выполнять SQL-запросы прямо внутри редактора кода.
