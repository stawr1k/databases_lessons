# Лекция 4: Связи между таблицами (JOIN), внешние ключи и транзакции (ACID)

## 1. Реляционные связи между сущностями

В реальных приложениях данные никогда не хранятся в одной гигантской таблице. Дублирование данных приводит к аномалиям обновления, избыточности и рискам рассинхронизации. Реляционная теория разделяет данные на независимые логические сущности, соединяемые связями.

### Основные типы отношений:

1. **Один-к-одному (1:1):**  
   Одной записи в таблице $A$ соответствует ровно одна запись в таблице $B$.  
   *Пример:* `users` (учетная запись) и `user_profiles` (паспортные данные, расширенные настройки). Поле внешнего ключа снабжается ограничением `UNIQUE`.
2. **Один-ко-многим (1:N):**  
   Одной записи в таблице $A$ может соответствовать множество записей в таблице $B$, но запись в $B$ принадлежит только одному родителю в $A$.  
   *Пример:* Один клиент (`users`) может сделать много заказов (`orders`). Внешний ключ `user_id` размещается в таблице заказов.
3. **Многие-ко-многим (M:N):**  
   Одной записи в таблице $A$ соответствует много записей в таблице $B$, и наоборот.  
   *Пример:* В одном заказе (`orders`) может быть много товаров (`products`), и один товар может присутствовать во множестве разных заказов.  
   *Реализация:* Всегда реализуется через третью **связующую таблицу (Junction Table)** — `order_items`.

```
[ Таблица users ] 1  <---->  N [ Таблица orders ] 1  <---->  N [ Таблица order_items ] N  <---->  1 [ Таблица products ]
```

## 2. Внешние ключи (FOREIGN KEY) и ссылочная целостность

**Внешний ключ (Foreign Key)** — это поле дочерней таблицы, которое ссылается на первичный ключ (`PRIMARY KEY`) родительской таблицы, обеспечивая целостность связей на уровне движка InnoDB.

```sql
-- Таблица пользователей
CREATE TABLE IF NOT EXISTS users (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE
) ENGINE=InnoDB;

-- Таблица заказов, ссылающаяся на users
CREATE TABLE IF NOT EXISTS orders (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    order_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    total_amount DECIMAL(10, 2) NOT NULL DEFAULT 0.00,
    status VARCHAR(20) NOT NULL DEFAULT 'NEW',
    
    -- Определение внешнего ключа с правилом каскадного удаления
    CONSTRAINT fk_orders_user 
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
) ENGINE=InnoDB;
```

### Поведение при удалении родительской записи (ON DELETE):

| Действие | Описание | Применение |
| :--- | :--- | :--- |
| **`CASCADE`** | При удалении родителя (пользователя) автоматически удаляются все его заказы. | Зависимые данные (позиции в чеке, настройки профиля). |
| **`RESTRICT` / `NO ACTION`** | Запрещает удаление родителя, пока у него есть хотя бы одна дочерняя запись. | Финансовые данные, аудит (нельзя случайно удалить клиента, если есть проводки). |
| **`SET NULL`** | Поле внешнего ключа в дочерней таблице заменяется на `NULL` (колонка должна быть `NULLABLE`). | Назначенный менеджер (при увольнении сотрудника сделка становится "ничейной"). |

## 3. Объединение таблиц (Виды JOIN)

Для выборки связанных данных из нескольких таблиц в одном SQL-запросе используются операторы `JOIN`.

```
        A               B                 A               B
    +-------+       +-------+         +-------+-------+-------+
    |   A   |       |   B   |         |       |       |       |
    | only  | ( A ∩ B ) | only  |         |   A   | A ∩ B |       |
    |       |       |       |         |       |       |       |
    +-------+-------+-------+         +-------+-------+-------+
            INNER JOIN                         LEFT JOIN
```

### 1. INNER JOIN (Внутреннее пересечение)
Возвращает только те строки, для которых найдено совпадение условий связи **в обеих таблицах**.

```sql
SELECT 
    orders.id AS order_id,
    users.username,
    users.email,
    orders.total_amount,
    orders.status
FROM orders
INNER JOIN users ON orders.user_id = users.id;
```

### 2. LEFT JOIN (Левое внешнее объединение)
Возвращает **все строки из левой таблицы**, даже если в правой таблице нет ни одного совпадения. Если соответствие отсутствует, поля правой таблицы заполняются значениями `NULL`.

```sql
-- Вывести всех пользователей и их заказы (включая тех, кто еще ничего не заказал)
SELECT 
    u.id AS user_id,
    u.username,
    o.id AS order_id,
    COALESCE(o.total_amount, 0.00) AS amount
FROM users u
LEFT JOIN orders o ON u.id = o.user_id;

-- Найти клиентов-"молчунов", которые зарегистрировались, но НЕ сделали ни одного заказа:
SELECT u.id, u.username, u.email
FROM users u
LEFT JOIN orders o ON u.id = o.user_id
WHERE o.id IS NULL;
```

### 3. RIGHT JOIN (Правое внешнее объединение)
Возвращает все строки из правой таблицы и совпавшие из левой. В современной разработке практически не используется, так как любой `RIGHT JOIN` читабельнее переписать в виде `LEFT JOIN`, поменяв таблицы местами.

### 4. FULL OUTER JOIN в MySQL
`FULL OUTER JOIN` возвращает все строки из обеих таблиц, объединяя их по совпадению. В MySQL нет нативного ключевого слова `FULL OUTER JOIN`, поэтому он эмулируется через `UNION` левого и правого объединений:

```sql
SELECT u.username, o.id AS order_id FROM users u LEFT JOIN orders o ON u.id = o.user_id
UNION
SELECT u.username, o.id AS order_id FROM users u RIGHT JOIN orders o ON u.id = o.user_id;
```

### 5. Объединение нескольких связанных таблиц

Запрос детализации заказа с извлечением имени покупателя, названий купленных товаров и их цен:

```sql
SELECT 
    o.id AS order_id,
    u.username AS customer,
    p.title AS product_name,
    oi.quantity,
    oi.price_per_unit,
    (oi.quantity * oi.price_per_unit) AS subtotal
FROM orders o
INNER JOIN users u ON o.user_id = u.id
INNER JOIN order_items oi ON o.id = oi.order_id
INNER JOIN products p ON oi.product_id = p.id
WHERE o.id = 101;
```

## 4. Транзакции и принципы ACID в MySQL (InnoDB)

**Транзакция** — это неделимая последовательность SQL-операций, которая либо применяется к базе данных целиком, либо не применяется вовсе.

Классический пример: перевод 1 000 рублей со счета клиента А на счет клиента Б.
1. `UPDATE accounts SET balance = balance - 1000 WHERE id = 1;`
2. `UPDATE accounts SET balance = balance + 1000 WHERE id = 2;`

Если между первой и второй командой пропадет питание сервера или разорвется сеть, без транзакции баланс А уменьшится, а на счет Б деньги не поступят. Транзакция гарантирует: деньги вернутся назад (`ROLLBACK`).

### Команды управления транзакциями (TCL)

* **`START TRANSACTION;`** (или `BEGIN;`) — открытие блока транзакции.
* **`COMMIT;`** — успешная фиксация всех изменений на диск.
* **`ROLLBACK;`** — полный откат всех изменений до состояния на момент старта.
* **`SAVEPOINT <имя>;`** — промежуточная точка сохранения внутри транзакции.
* **`ROLLBACK TO <имя>;`** — частичный откат изменений до точки сохранения.

```sql
-- Демонстрация безопасного перевода средств
START TRANSACTION;

-- Шаг 1: Списываем деньги
UPDATE accounts SET balance = balance - 1000.00 WHERE id = 1 AND balance >= 1000.00;

-- Шаг 2: Начисляем деньги
UPDATE accounts SET balance = balance + 1000.00 WHERE id = 2;

-- Если обе операции завершились без ошибок:
COMMIT;

-- В случае ошибки в коде приложения вызывается:
-- ROLLBACK;
```

## 5. Уровни изоляции транзакций (Isolation Levels)

При параллельной работе сотен пользователей с одной базой данных возможны конфликты:
* **Dirty Read (Грязное чтение):** Транзакция видит незафиксированные изменения другой параллельной транзакции.
* **Non-repeatable Read (Неповторяющееся чтение):** Повторный запрос одних и тех же данных внутри транзакции возвращает разные значения из-за `UPDATE` параллельной транзакции.
* **Phantom Read (Фантомное чтение):** Повторный поиск по диапазону возвращает новые добавленные строки (`INSERT`) другой транзакции.

| Уровень изоляции | Грязное чтение | Неповторяющееся чтение | Фантомное чтение | Описание |
| :--- | :---: | :---: | :---: | :--- |
| **`READ UNCOMMITTED`** | Да | Да | Да | Самый быстрый, но опасный. Читает "чужой черновик". |
| **`READ COMMITTED`** | Нет | Да | Да | Читает только закоммиченные данные. Стандарт в PostgreSQL/Oracle. |
| **`REPEATABLE READ`** | **Нет** | **Нет** | **Нет (в InnoDB)** | **Стандартный уровень по умолчанию в MySQL InnoDB!** Предотвращает фантомы через механизм MVCC и Next-Key блокировки. |
| **`SERIALIZABLE`** | Нет | Нет | Нет | Строго последовательное выполнение. Все операции чтения неявно блокируются. Минимальная производительность. |

### Блокировка строк от состояния гонки (SELECT ... FOR UPDATE)

Если двум пользователям одновременно нужно забронировать последний оставшийся товар на складе, используется пессимистическая блокировка строки:

```sql
START TRANSACTION;

-- Блокируем строку товара для других транзакций до конца нашей транзакции:
SELECT stock_quantity FROM products WHERE id = 42 FOR UPDATE;

-- Обновляем остаток
UPDATE products SET stock_quantity = stock_quantity - 1 WHERE id = 42;

COMMIT;
```
