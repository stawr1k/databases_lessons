# Лекция 4: Работа с TTL, Expire, Pub/Sub и транзакциями в Redis

## 1. Время жизни ключей (TTL и Expire)

Для любого ключа в Redis можно задать время существования. По истечении этого времени ключ автоматически удаляется из базы данных.

### Команды и статусы TTL

* **`EXPIRE <ключ> <секунды>`** — задает время жизни существующего ключа в секундах.  
* **`TTL <ключ>`** — возвращает оставшееся время жизни ключа в секундах:  
&nbsp;&nbsp;&nbsp;&nbsp;`-1`: ключ бессрочный (время жизни не ограничено).  
&nbsp;&nbsp;&nbsp;&nbsp;`-2`: ключ не существует или его время жизни истекло и он был удален.  
* **`PERSIST <ключ>`** — сбрасывает таймер `EXPIRE`, делая ключ постоянным (бессрочным).  
* При создании базовой строки ключ с ограничением по времени создается через параметр `EX`:  
&nbsp;&nbsp;&nbsp;&nbsp;`SET <ключ> <значение> EX <секунды>`

> **Важно:** Для сложных структур данных (`Lists`, `Hashes`, `Sets`) опцию `EX` при создании указать нельзя. Сначала создается структура (`LPUSH`, `HSET` и т.д.), а затем отдельной командой вызывается `EXPIRE <ключ> <секунды>`.

### Примеры использования

```redis
> SET cache_data "some_value"
OK
> EXPIRE cache_data 60
(integer) 1
> TTL cache_data
(integer) 54
```

## 2. Механизм Publish / Subscribe (Pub/Sub)

Redis содержит встроенную систему обмена сообщениями в реальном времени по шаблону «Издатель — Подписчик».

### Принцип работы

* **Подписчик (Subscriber)** подписывается на один или несколько текстовых каналов и находится в ожидании сообщений.  
* **Издатель (Publisher)** публикует текстовые сообщения в определенный канал. Все активные подписчики мгновенно получают это сообщение.

### Команды

* **`SUBSCRIBE <канал>`** — подписывается на сообщения из указанного канала.  
&nbsp;&nbsp;&nbsp;&nbsp;Пример: `SUBSCRIBE News`  
* **`PUBLISH <канал> <сообщение>`** — отправляет сообщение в канал.  
&nbsp;&nbsp;&nbsp;&nbsp;Пример: `PUBLISH News "Breaking News"`  
* **`UNSUBSCRIBE <канал>`** — отписывает клиента от указанного канала.

## 3. Транзакции и пакетное выполнение (MULTI, EXEC)

Транзакции в Redis позволяют сгруппировать несколько команд в отдельную очередь и выполнить их последовательно и атомарно.

### Принцип работы

* Вызов команды `MULTI` переводит клиент в режим транзакции. Все последующие команды не выполняются сразу, а помещаются в очередь (`QUEUED`).  
* Вызов команды `EXEC` запускает выполнение всех накопленных в очереди команд за один проход.

### Пример использования

```redis
> MULTI
OK
> SET UserBalance:1 100
QUEUED
> INCRBY UserBalance:1 50
QUEUED
> DECRBY UserBalance:1 30
QUEUED
> EXEC
1) OK
2) (integer) 150
3) (integer) 120
```

### Зачем нужны транзакции?

Транзакции гарантируют **согласованность данных (Data Consistency)**, если несколько связанных операций должны либо выполниться строго вместе, либо не выполниться вовсе (например, перевод денег: обновление баланса пользователя и одновременное добавление записи в историю транзакций).
