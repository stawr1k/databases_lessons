# Лекция 6: Кеширование данных с помощью Redis на Python

## 1. Введение: Зачем нужно кеширование?
В реальных веб-проектах бэкенд-приложения часто выполняют ресурсоемкие операции, например, обращаются к сторонним API-сервисам или делают сложные SQL-запросы к основным базам данных. Обработка таких запросов всегда занимает определенное время. Если каждый пользователь при обновлении страницы будет заставлять сервер заново выполнять эти вычисления, система быстро перегрузится.

**Кеширование** позволяет оптимизировать проекты и существенно сократить ресурсы на повторение операций. Результат первого запроса помещается в сверхбыструю базу данных Redis. При последующих обращениях приложение моментально подтягивает уже готовые данные из кеша, минуя тяжелые повторные вычисления.


## 2. Архитектура работы кеша

1. **Запрос данных:** Приложение пробует найти нужную запись по определенному ключу в Redis.
2. **Попадание в кеш (Cache Hit):** Если данные успешно найдены, программа выводит уведомление о попадании в кеш, декодирует бинарный ответ от Redis в обычную строку и сразу возвращает результат пользователю, завершая выполнение функции.
3. **Промах кеша (Cache Miss):** При самом первом запросе данных в Redis еще нет, поэтому условие поиска не срабатывает. Скрипт обращается к источнику данных (API или БД), берет результат, записывает его в Redis по нашему ключу с ограничением по времени жизни (TTL), а затем отдает пользователю.


## 3. Практическая реализация проекта

Для написания кода используются библиотека `redis` для взаимодействия с базой данных и модуль `time` для искусственной имитации задержек. Перед запуском скрипта сервер Redis должен быть запущен.

### Полный код программы кеширования:

```python
import time
import redis

# 1. Настройка подключения к нужной базе данных
# Подключаемся к localhost, стандартному порту и выбираем нулевую базу данных
client = redis.Redis(host="localhost", port=6379, db=0)

def fake_api_query(user_id):
    """
    Функция, имитирующая тяжелый и долгий запрос к стороннему API 
    или основной реляционной базе данных.
    """
    # В реальной программе здесь описывается подключение к БД или отправка HTTP-запроса
    # Для демонстрации мы просто приостанавливаем выполнение программы
    time.sleep(2)
    
    # Возвращаем сформированную строку с данными профиля
    return f"User Profile. User ID: {user_id}"


def get_user_profile(user_id):
    """
    Основная функция получения профиля, реализующая логику кеширования.
    """
    # Формируем уникальный ключ, по которому будем сохранять и искать записи в Redis
    cache_key = f"user:{user_id}:profile"
    
    # Пытаемся найти запись в базе данных Redis по нашему ключу
    cached_data = client.get(cache_key)
    
    # Проверяем, нашли ли мы данные в кеше
    if cached_data:
        print("Cash Hit")  # Сообщаем об успешном попадании в кеш
        # Преобразуем байты от Redis в обычную строку с помощью функции decode()
        return cached_data.decode('utf-8')
        
    # Если в кеше данных нет, выполняется последующий код
    # Запрашиваем данные из источника
    profile_data = fake_api_query(user_id)
    
    # Записываем полученный результат в кеш Redis
    # Устанавливаем значение в кеше на определенное количество времени (на 60 секунд)
    client.setex(cache_key, 60, profile_data)
    
    return profile_data


# --- Демонстрация работы приложения ---
if __name__ == "__main__":
    # Вызываем одну и ту же функцию два раза для одного ID пользователя
    print("Первый запрос (данных в кеше еще нет):")
    print(get_user_profile(1))
    
    print("\nВторой запрос (данные должны подтянуться из кеша):")
    print(get_user_profile(1))
```



## 4. Разбор результатов выполнения скрипта

При запуске написанной программы наглядно видна разница в поведении системы при первом и повторном обращении:

* **Первое обращение:** Скрипт проверяет наличие ключа, видит, что информации в Redis нет, и начинает выполнять функцию имитации запроса. Программа ожидает получения данных из-за искусственной задержки, после чего выводит полученные данные на экран и параллельно сохраняет их в Redis с ограничением времени жизни.
* **Второе обращение:** При повторном вызове функции с тем же идентификатором пользователя программа делает проверку и обнаруживает, что данные уже успешно записаны в заданный ключ в Redis. Срабатывает условный оператор, данные извлекаются из оперативной памяти, декодируются и выводятся на экран. Подгрузка данных происходит абсолютно мгновенно.



## 5. Заключение
Работа с кешем в Redis является простой и во многом автоматизированной. Помещение ресурсоемких запросов в Redis позволяет первому пользователю выполнить полную загрузку, а всем последующим — получать информацию из кеша моментально. Это делает Redis незаменимым инструментом для оптимизации и ускорения современных веб-приложений.
