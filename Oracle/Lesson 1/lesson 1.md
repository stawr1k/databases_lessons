# Лекция 1: Введение в Oracle Database, мультиарендная архитектура (CDB/PDB) и развертывание

## 1. Что такое Oracle Database?

**Oracle Database** — это флагманская объектно-реляционная система управления базами данных (СУБД) корпоративного уровня от корпорации Oracle, являющаяся мировым стандартом в сфере критически важных (Mission-Critical) бизнес-систем, банковского сектора, телекома и масштабных ERP-платформ.

В отличие от многих открытых СУБД общего назначения, Oracle Database изначально разрабатывалась с прицелом на колоссальные объемы данных (сотни терабайт и петабайт), параллельную обработку тысяч одновременных транзакций и непрерывную доступность 24/7/365 с нулевым временем простоя.

Современные версии СУБД (актуальные релизы **Oracle Database 19c Long-Term Support (LTS)** и новейшая **Oracle Database 23ai**) представляют собой конвергентную платформу, поддерживающую:
* Классические реляционные таблицы и целостность связей.
* Встроенный процедурный язык **PL/SQL**.
* Нативное хранение и индексацию документов **JSON** (включая JSON-реляционную дуальность в 23ai).
* Пространственные геоданные (Oracle Spatial) и графовые модели.
* Векторный поиск на базе искусственного интеллекта (AI Vector Search).

## 2. Ключевые преимущества и причины доминирования в Enterprise

* **Непревзойденная надежность и многоверсионность (MVCC):**  
&nbsp;&nbsp;&nbsp;&nbsp;В Oracle реализована образцовая модель изоляции: **читатели никогда не блокируют писателей, а писатели никогда не блокируют читателей**. Согласованное чтение на определенную точку во времени обеспечивается сегментами отката (Undo Tablespace).
* **Кластеризация высокой доступности (Oracle RAC & Data Guard):**  
&nbsp;&nbsp;&nbsp;&nbsp;Технология *Real Application Clusters (RAC)* позволяет нескольким физическим серверам работать с единой базой данных на общем хранилище, а *Data Guard* гарантирует мгновенное аварийное переключение на резервный ЦОД в любой точке планеты.
* **Встроенный компилятор PL/SQL:**  
&nbsp;&nbsp;&nbsp;&nbsp;Язык PL/SQL исполняется непосредственно внутри движка базы данных на уровне виртуальной машины сервера, исключая накладные расходы сети на передачу промежуточных данных в клиентское приложение.
* **Продвинутое секционирование (Partitioning):**  
&nbsp;&nbsp;&nbsp;&nbsp;Таблицы с миллиардами строк автоматически разделяются на физические секции по датам, диапазонам или спискам, что позволяет сканировать только нужные сегменты диска.
* **Глубокая безопасность:**  
&nbsp;&nbsp;&nbsp;&nbsp;Прозрачное шифрование данных на диске (TDE — Transparent Data Encryption), детальный аудит доступа и разграничение прав на уровне строк (VPD — Virtual Private Database).

## 3. Архитектура Oracle: Инстанс, База данных и Мультиарендность (CDB / PDB)

Одно из ключевых концептуальных отличий Oracle от других СУБД — строгое разделение понятий **Инстанс (Instance)** и **База данных (Database)**:

```
+---------------------------------------------------------------+
|               ИНСТАНС ORACLE (ORACLE INSTANCE)                |
|  Память (SGA): Shared Pool, Buffer Cache, Redo Log Buffer    |
|  Фоновые процессы: DBWn, LGWR, CKPT, SMON, PMON, ARCn         |
+---------------------------------------------------------------+
                               |
                               v
+---------------------------------------------------------------+
|             ФИЗИЧЕСКАЯ БАЗА ДАННЫХ (DATABASE)                 |
|  Файлы данных (.dbf), Контрольные файлы (.ctl), Redo-логи    |
+---------------------------------------------------------------+
```

1. **Инстанс (Экземпляр):** Совокупность выделенной оперативной памяти (**SGA** — System Global Area) и набора системных фоновых процессов операционной системы.
   * `DBWn` (Database Writer) — сбрасывает "грязные" измененные блоки данных из RAM на физический диск.
   * `LGWR` (Log Writer) — фиксирует записи транзакций в Redo Log файлы перед коммитом (гарантия Durability в ACID).
   * `CKPT` (Checkpoint) — синхронизирует контрольные точки между памятью и заголовками файлов данных.
   * `SMON / PMON` — автоматическое восстановление после сбоев и очистка ресурсов зависших клиентских сессий.
2. **База данных:** Физические файлы на накопителе (файлы табличных пространств, контрольные файлы структуры и журналы повторного воспроизведения).

### Мультиарендная архитектура (Multitenant Architecture)

Начиная с версии Oracle 12c и во всех современных релизах (19c, 21c, 23ai) используется концепция контейнеров:

```
                    +------------------------------------+
                    |       CDB$ROOT (Корневой контур)    |
                    |  (Системные словари, метаданные)   |
                    +------------------------------------+
                                      |
            +-------------------------+-------------------------+
            |                                                   |
            v                                                   v
+-----------------------+                           +-----------------------+
|  PDB$SEED (Шаблон)    |                           |  FREEPDB1 / ORCLPDB1  |
|  (Только для чтения)  |                           |  (Подключаемая БД     |
+-----------------------+                           |   с нашими данными!)  |
                                                    +-----------------------+
```

* **CDB (Container Database — `CDB$ROOT`):** Корневая управляющая база данных. В ней хранятся глобальные системные представления и метаданные СУБД.
* **PDB (Pluggable Database — например, `FREEPDB1`):** Автономная, независимая «подключаемая» база данных. Каждая PDB содержит собственные таблицы, схемы, пользователей и права.

> **🛑 Главная ловушка для начинающих в Oracle:**  
> При прямом подключении от имени суперпользователя `SYS` по умолчанию вы попадаете в корневой контейнер `CDB$ROOT`. Если попытаться создать там обычного пользователя: `CREATE USER alex IDENTIFIED BY pass;`, Oracle выдаст ошибку `ORA-65096: invalid common user or role name`.  
> В `CDB$ROOT` можно создавать только системных пользователей с префиксом `c##` (например, `c##alex`).  
> **Правильный подход:** Все прикладные таблицы и пользовательские схемы создаются **внутри конкретной PDB** (например, `FREEPDB1`). Перед созданием пользователей необходимо либо сразу подключаться к сервису PDB, либо переключить сессию командой:
> ```sql
> ALTER SESSION SET CONTAINER = FREEPDB1;
> ```

## 4. Установка и развертывание Oracle Database

Для целей локальной разработки и обучения корпорация Oracle предоставляет полностью бесплатную редакцию **Oracle Database 23ai Free** (ранее Express Edition — XE).

### Вариант 1: Запуск через Docker (Рекомендуемый современный стандарт)

Запуск через Docker изолирует тяжелые службы СУБД от операционной системы и поднимается за несколько минут.

#### Запуск одной командой через Docker CLI:

```bash
docker run --name oracle23ai -p 1521:1521 -e ORACLE_PASSWORD=MyStrongPassword123! -d container-registry.oracle.com/database/free:latest
```

| Параметр | Описание |
| :--- | :--- |
| `--name oracle23ai` | Человекочитаемое имя контейнера |
| `-p 1521:1521` | Стандартный сетевой порт прослушивателя Oracle (TNS Listener) |
| `-e ORACLE_PASSWORD=...` | Пароль администратора для учетных записей `SYS`, `SYSTEM` |
| `container-registry.oracle.com/...` | Официальный образ Oracle Database 23ai Free из реестра Oracle |

#### Запуск через Docker Compose (Идеально для постоянного окружения):

Создайте файл `docker-compose.yml`:

```yaml
services:
  oracle:
    image: container-registry.oracle.com/database/free:latest
    container_name: oracle_dev
    restart: always
    environment:
      ORACLE_PASSWORD: MyStrongPassword123!
    ports:
      - "1521:1521"
    volumes:
      - oracle_data:/opt/oracle/oradata

volumes:
  oracle_data:
```

Запуск сервиса:

```bash
docker compose up -d
```

### Вариант 2: Локальная установка на Linux / Windows

При необходимости нативной установки можно загрузить установщик с официального портала [Oracle Database Free Downloads](https://www.oracle.com/database/technologies/free-downloads.html):
* **Linux (Oracle Linux / RHEL / Ubuntu):** Устанавливается через RPM-пакет (`sudo dnf install oracle-database-free-23ai-1.0-1.el8.x86_64.rpm`), после чего запускается мастер начальной инициализации `/etc/init.d/oracle-free-23ai configure`.
* **Windows:** Установка выполняется через графический инсталлятор `setup.exe` с указанием системного пароля.

## 5. Подключение к Oracle через консольные клиенты

### Консольный клиент SQL\*Plus

`SQL*Plus` — классическая консольная утилита командной строки, поставляемая с каждым сервером Oracle.

#### Подключение внутри Docker-контейнера от имени администратора SYS:

```bash
docker exec -it oracle23ai sqlplus sys/MyStrongPassword123!@//localhost:1521/FREEPDB1 as sysdba
```

#### Базовые команды проверки состояния в SQL\*Plus:

```sql
-- Проверка текущей версии установленной СУБД
SELECT banner_full FROM v$version;

-- Проверка активного контейнера (должен быть FREEPDB1)
SHOW CON_NAME;

-- Просмотр открытых подключаемых баз (PDB)
SHOW PDBS;

-- Выход из интерактивной консоли
EXIT;
```

> **💡 Лайфхак: Утилита SQLcl**  
> В современной экосистеме Oracle на смену старому SQL\*Plus пришла бесплатная утилита **Oracle SQLcl** (SQL Command Line). Она поддерживает цветную подсветку синтаксиса, клавишу автодополнения Tab, историю стрелками и мгновенный экспорт в форматы CSV/JSON через команду `SET SQLFORMAT json`.

## 6. Графические клиенты (GUI) для разработки

Для комфортного проектирования схем, написания SQL-запросов и отладки PL/SQL-кода рекомендуется использовать:

* **[Oracle SQL Developer](https://www.oracle.com/database/sqldeveloper/):** Официальный мощный бесплатный инструмент от Oracle для разработчиков и администраторов баз данных (включает построение ER-диаграмм, профилировщик запросов и отладчик PL/SQL).
* **[Oracle Developer Tools for VS Code](https://marketplace.visualstudio.com/items?itemName=Oracle.oracle-devtools):** Официальное расширение для редактора Visual Studio Code, позволяющее просматривать дерево объектов, выполнять скрипты и редактировать процедуры прямо в IDE.
* **[DBeaver Community](https://dbeaver.io/):** Универсальный клиент с превосходной поддержкой Oracle через JDBC.

### Параметры подключения в графических клиентах:

| Поле подключения | Значение по умолчанию |
| :--- | :--- |
| **Хост (Host)** | `localhost` (или IP-адрес сервера) |
| **Порт (Port)** | `1521` |
| **Тип соединения** | **Service Name** (Имя службы) |
| **Имя службы (Service Name)** | `FREEPDB1` *(для 23ai)* или `XEPDB1` *(для 18c/21c XE)* |
| **Пользователь (User)** | `SYSTEM` (или созданный прикладной пользователь) |
| **Пароль (Password)** | Заданный вами при развертывании контейнера |
