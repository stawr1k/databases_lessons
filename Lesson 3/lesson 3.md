# Лекция 3: Продвинутые структуры данных в Redis

## 1. Введение

В предыдущих уроках изучалась работа с базовым типом данных — простыми строками («ключ-значение»). В этом уроке рассматриваются сложные структуры данных Redis: неупорядоченные множества (Sets), упорядоченные множества (Sorted Sets / ZSet), списки (Lists), структурированные хэш-таблицы (Hashes) и вероятностный алгоритм HyperLogLog.

## 2. Неупорядоченные множества (Sets)

**Множество (Set)** — это неупорядоченная коллекция элементов, где каждое значение гарантированно уникально. Повторные попытки добавить существующий элемент игнорируются.

В отличие от обычных списков, где элементы могут дублироваться и хранятся в строгом порядке добавления, **Set в Redis** устроен как математическое множество. Внутри него элементы находятся в хаотичном (неупорядоченном) состоянии, но сервер обеспечивает мгновенный контроль уникальности на уровне ядра.

**Внутреннее устройство и производительность**
Redis реализует Sets с помощью хэш-таблиц (где элементы множества являются ключами со значениями-заглушками). Благодаря этому операции проверки наличия элемента, добавления и удаления выполняются за **константное время \(O(1)\)**. 

Это означает, что скорость поиска элемента в множестве из 10 элементов и множестве из 1 000 000 элементов будет абсолютно одинаковой — вычисления происходят практически мгновенно.

### Главные особенности множеств:

1. **Строгая уникальность:** Вы можете отправлять одну и ту же строку в множество сотни раз, но Redis сохранит её в единственном экземпляре. Повторные операции добавления просто вернут `0` и не заберут лишнюю память.
2. **Отсутствие индексов:** Так как коллекция неупорядоченная, вы не можете запросить «первый», «пятый» или «последний» элемент. Доступ осуществляется либо ко всей коллекции сразу, либо по конкретному значению.
3. **Мощные математические операции:** На уровне сервера Redis умеет пересекать, объединять и находить разность между несколькими множествами. Это позволяет избегать скачивания гигабайтов данных в код приложения — все вычисления происходят прямо в оперативной памяти базы данных.

### Команды работы с Sets

| Команда | Описание |
| :--- | :--- |
| `SADD <ключ> <значение1> [значение2 ...]` | Добавляет один или несколько элементов в множество. Возвращает количество реально добавленных (новых) элементов. |
| `SMEMBERS <ключ>` | Выводит все элементы, хранящиеся в множестве. |
| `SREM <ключ> <значение>` | Удаляет указанный элемент из множества. |
| `DEL <ключ>` | Полное удаление множества по его ключу. |

### Примеры использования

```redis
> SADD users:online "Alice" "Bob" "Charlie"
(integer) 3
> SMEMBERS users:online
1) "Alice"
2) "Bob"
3) "Charlie"
> SREM users:online "Bob"
(integer) 1
```

## 3. Упорядоченные множества (Sorted Sets / ZSet)

**Упорядоченное множество (ZSet)** — аналог стандартного множества, но с дополнительным числовым параметром **Score (вес / очки)** для каждого элемента. Redis автоматически сортирует элементы множества по возрастанию их значения Score.

В то время как обычные множества (Sets) хранят данные в хаотичном порядке, `Sorted Set (ZSet)` — это одна из самых мощных и гибких структур в Redis. Она решает извечную проблему разработчиков: как сохранить абсолютную уникальность элементов, но при этом иметь возможность мгновенно извлекать их в отсортированном виде.

### Как работает параметр Score?

Каждому элементу (member) в ZSet жестко присваивается числовое поле — **Score (весовой коэффициент / очки)**. Это число может быть как целым, так и с плавающей точкой (дробным), а также принимать отрицательные значения. 

Redis постоянно следит за состоянием коллекции и **автоматически перестраивает** порядок элементов при любом изменении. Сортировка по умолчанию идет от меньшего Score к большему (по возрастанию). Если у нескольких разных элементов значения Score совпадают, Redis сортирует их между собой в лексикографическом (алфавитном) порядке.

**Внутреннее устройство: Skip List + Hash Map:**

Sorted Set реализуется с помощью комбинации двух структур данных: **хэш-таблицы** и **вероятностного списка пропусков (Skip List)**. 

* Хэш-таблица обеспечивает уникальность элементов и позволяет мгновенно узнать Score конкретного элемента по его имени за время O(1).
* Список пропусков отвечает за упорядоченность и гарантирует, что добавление, удаление и поиск элементов по диапазону очков происходят за **логарифмическое время \(O(\log N)\)**. Даже если в вашем лидерборде находятся 10 000 000 игроков, выборка топ-10 лучших займет считанные микросекунды.

### Главные преимущества ZSet:
1. **Динамическая сортировка «на лету»:** Приложению больше не нужно тратить ресурсы процессора на сортировку массивов в коде или выполнять тяжелые SQL-запросы с оператором `ORDER BY`. Данные *всегда* лежат в памяти в отсортированном виде.
2. **Выборка по диапазонам:** Вы можете мгновенно вырезать из базы кусок данных — например, «выдать элементы со Score от 100 до 500» или «показать топ-5 элементов с конца списка».

### Команды работы с Sorted Sets

| Команда | Описание |
| :--- | :--- |
| `ZADD <ключ> <score> <значение>` | Добавляет элемент с числовым значением Score в упорядоченное множество. |
| `ZRANGE <ключ> <старт> <конец> [WITHSCORES]` | Возвращает элементы из диапазона индексов. |

### Особенности работы:

* Опция `WITHSCORES` выводит не только имена элементов, но и их числовые баллы Score.  
* Индексы `0 -1` выводят все элементы множества от меньшего Score к большему.

### Примеры использования

```redis
> ZADD leaderboard 100 "Alice"
(integer) 1
> ZADD leaderboard 200 "Bob" 150 "Charlie"
(integer) 2
> ZRANGE leaderboard 0 -1 WITHSCORES
1) "Alice"
2) "100"
3) "Charlie"
4) "150"
5) "Bob"
6) "200"
```

## 4. Списки (Lists)

**Список (List)** — это упорядоченная коллекция строк, поддерживающая дубликаты. Работа со списками происходит строго через края: добавление и извлечение производится либо в **начало (слева / Left)**, либо в **конец (справа / Right)**.

В отличие от множеств (Sets), где уникальность на первом месте, **Lists в Redis** ориентированы на строгий хронологический порядок. Списки работают по принципу последовательностей, где каждый элемент четко знает своего «соседа» слева и справа. Это позволяет хранить историю действий, сообщения или задачи в том порядке, в котором они поступали.

### Внутреннее устройство: Связанные списки (Linked Lists)

Главное отличие списков Redis от обычных массивов в языках программирования (например, в Python или JavaScript) заключается в том, что под капотом они реализованы как **двусвязные списки** (а в современных версиях Redis — как оптимизированные структуры *Quicklists*). 

Из этой архитектурной особенности вытекают важные правила производительности:

* **Мгновенный доступ к краям \(O(1)\):** Добавление элемента в самое начало (голову) или в самый конец (хвост) списка, а также извлечение элементов оттуда происходит за константное время. Будь в списке 10 элементов или 10 миллионов, операция добавления на «края» займет одинаково ничтожное время.
* **Тяжелый доступ к середине \(O(N)\):** Поиск, удаление или чтение элементов по индексу из середины списка требуют последовательного перебора элементов с одного из краев. Поэтому списки в Redis редко используют как классические индексированные массивы.

### Главные особенности списков:

1. **Поддержка дубликатов:** Вы можете добавить строку `"привет"` десять раз подряд, и Redis послушно сохранит десять одинаковых элементов в заданной последовательности.
2. **Двунаправленность:** Вы можете организовать стек (LIFO — Last In, First Out), добавляя и забирая элементы с одного края, либо классическую очередь (FIFO — First In, First Out), добавляя элементы с одного конца, а забирая с другого.
3. **Блокирующее чтение:** Redis поддерживает специальные блокирующие команды для списков. Если очередь пуста, вокер (обработчик) засыпает и не нагружает процессор холостыми запросами. Как только в список падает новый элемент, Redis мгновенно «будит» вокера и передает ему задачу.

### Команды работы со Списками

| Команда | Описание |
| :--- | :--- |
| `LPUSH <ключ> <значение>` | Добавляет элемент в начало (слева) списка. |
| `RPUSH <ключ> <значение>` | Добавляет элемент в конец (справа) списка. |
| `LPOP <ключ>` | Удаляет и возвращает первый (левый) элемент списка. |
| `RPOP <ключ>` | Удаляет и возвращает последний (правый) элемент списка. |
| `LRANGE <ключ> <старт> <конец>` | Возвращает элементы списка в диапазоне индексов. |
| `LLEN <ключ>` | Возвращает текущее количество элементов в списке. |
| `LINDEX <ключ> <индекс>` | Возвращает элемент по его индексу в списке. |

### Примеры использования

```redis
> RPUSH tasks "task1" "task2"
(integer) 2
> LPUSH tasks "urgent_task"
(integer) 3
> LRANGE tasks 0 -1
1) "urgent_task"
2) "task1"
3) "task2"
> LPOP tasks
"urgent_task"
```

## 5. Вероятностная структура HyperLogLog

**HyperLogLog** — специализированная вероятностная структура данных, предназначенная для эффективного и сверхбыстрого подсчета уникальных элементов (кардинальности) с минимальным потреблением оперативной памяти (около 12 КБ независимо от объема данных).

### Главные особенности HyperLogLog:
1. **Только подсчет:** Из HLL-ключа невозможно извлечь данные обратно. Вы не можете спросить у Redis: «А какие именно пользователи заходили на сайт?». Единственный ответ, который дает эта структура — это `количество` уникальных элементов.
2. **Атомарное слияние:** Redis умеет на лету объединять несколько разных HLL-ключей в один новый. Например, имея статистику уникальных посетителей за понедельник, вторник и среду (три отдельных ключа по 12 КБ), можно моментально получить общее количество уникальных гостей за все 3 дня без дублирования.

### Команды работы с HyperLogLog

| Команда | Описание |
| :--- | :--- |
| `PFADD <ключ> <элемент1> [элемент2 ...]` | Добавляет элементы в структуру (например, IP-адреса посетителей). |
| `PFCOUNT <ключ>` | Возвращает приближенное количество уникальных элементов. Повторные добавления одинаковых элементов не меняют результат и игнорируются. |

### Примеры использования

```redis
> PFADD unique_visitors "192.168.0.1" "192.168.0.2" "10.0.0.1"
(integer) 1
> PFADD unique_visitors "192.168.0.1"
(integer) 0
> PFCOUNT unique_visitors
(integer) 3
```

## 6. Хэш-таблицы (Hashes)

**Хэш (Hash)** — это полноценный словарь (объект) внутри Redis, позволяющий хранить внутри одного ключа набор полей и значений (поля типа `field-value`). Идеально подходит для представления сложных объектов (пользователи, товары и т.д.).

Если в реляционных базах данных для хранения объекта (например, пользователя) требуется отдельная строка в таблице, а в документо-ориентированных СУБД (вроде MongoDB) — JSON-документ, то в Redis для этих целей существует структура **Hashes**. По сути, это встроенная «мини-база данных» или плоский ассоциативный массив, привязанный к одному конкретному ключу.
Hashes позволяют напрямую читать, перезаписывать или удалять отдельные поля объекта (`field`) на стороне сервера за константное время **\(O(1)\)**, совершенно не трогая остальные данные.

### Главные особенности хэшей:
1. **Плоская структура:** Поля хэша внутри Redis не могут содержать вложенные структуры (например, списки или другие хэши). Значением любого поля всегда является обычная строка (`String`).
2. **Атомарные счетчики внутри полей:** Как и в случае с обычными строками, в хэшах есть специальные команды для увеличения числовых полей на заданный шаг. Вы можете атомарно инкрементировать баланс пользователя или количество товаров на складе прямо внутри объекта.

### Команды работы с Hashes

| Команда | Описание |
| :--- | :--- |
| `HSET <ключ> <поле1> <значение1> [...]` | Устанавливает одно или несколько полей объекта. |
| `HGET <ключ> <поле>` | Получает значение конкретного поля объекта. |
| `HGETALL <ключ>` | Возвращает все поля и их значения для указанного объекта. |
| `HDEL <ключ> <поле>` | Удаляет конкретное поле из объекта. |
| `DEL <ключ>` | Полностью удаляет объект-хэш из базы данных. |

### Примеры использования

```redis
> HSET User:1 name "Alice" age "30" email "alice@example.com"
(integer) 3
> HGET User:1 name
"Alice"
> HGETALL User:1
1) "name"
2) "Alice"
3) "age"
4) "30"
5) "email"
6) "alice@example.com"
> HDEL User:1 age
(integer) 1
```
